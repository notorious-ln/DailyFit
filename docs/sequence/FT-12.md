# FT-12. Предложение по корректировке питания

Каждый пункт содержит задачу, предлагаемое изменение и причину.

Допустимые изменения: заменить пример блюда или сдвинуть суточную калорийность.

За одну принятую рекомендацию калорийность изменяется не более чем на 10 процентов.

Предложение не опускает калорийность ниже 80 процентов от рассчитанного поддержания. Если шаг упирается в границу, он обрезается, и пользователь видит это в причине.

Метки ограничений не дают предложить запрещённый тип нагрузки. Для питания учитываются только те ограничения, которые заданы метками, а не догадкой модели.

```mermaid
sequenceDiagram
    actor User as Пользователь
    participant FE as Frontend
    participant Assistant as Assistant Service
    participant Rules as Rules Engine
    participant Rec as Recommendation Service
    participant Plan as Plan Service
    participant DB as Database

    User->>FE: Разобрать день или неделю
    FE->>Assistant: POST /analyze
    Assistant->>DB: Сводка задач и дневника, активный meal-план
    Assistant->>Rules: Черновики правок питания
    Rules->>Rules: Лимит 10 процентов, пол 80 процентов поддержания, метки еды
    alt Есть допустимые пункты
        Assistant->>DB: Recommendation status draft
        Assistant-->>FE: Комментарий и пункты
    else Пунктов нет
        Assistant-->>FE: Только комментарий
    end

    User->>FE: Принимает или отклоняет пункты
    FE->>Rec: POST /recommendations/{id}/decide
    alt Отклонить
        Rec->>DB: status rejected
    else Принять
        Rec->>DB: BEGIN
        Rec->>Plan: Применить только к будущим meal-задачам и активному плану
        Rec->>DB: status accepted или partially_accepted
        Rec->>DB: COMMIT
    end
```
